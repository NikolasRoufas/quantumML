# QuantumML — Final Experimental Results for Journal Revision (Round 2)

This is an experimental results report, not a manuscript section. It documents what was
actually implemented and run in response to the second-round reviewer concerns, with
pointers to the raw evidence for each claim. All numbers below come from the files in this
directory or in `results/revision/`, generated by actually executing the code in this
repository — nothing here is projected or estimated.

**Repository:** https://github.com/NikolasRoufas/quantumML (branch `journal-revision-round2`)

## Reviewer concern A — Repeated train/test splits

**What changed:** `split_robustness.py` was rewritten to separate two previously-conflated
sources of variability and to add quantum-kernel SVMs, which the prior version explicitly
omitted.

- **`fixed_subset` (primary):** the 2,000-sample quantum data subsample is drawn once;
  only the stratified 1,400/600 train/test partition varies across 5 seeds
  (`42, 123, 456, 789, 2026`).
- **`varying_subset` (secondary/sensitivity):** both the subsample and the partition vary
  together per seed — the original design, kept for comparison.
- 3 independent initialization seeds (`7001, 7002, 7003`, disjoint from the split seeds)
  per VQC/split combination, aggregated within each split before any split-level
  comparison.
- QK-SVM (3 kernels × 5 splits = 15 runs) now included in the repeated-split sweep.

**What was executed:** 135 VQC runs (9 configs × 5 splits × 3 inits) in each of the two
variants, 15 QK-SVM runs, 15 classical-baseline runs per variant — **all currently
succeeding** (see Grid Completeness below).

**Main results** (fixed-subset, mean ± SD across 5 splits; VQC/QK-SVM first averaged over
3 init seeds per split):

| Method | Accuracy | F1 |
|---|---|---|
| SVM (RBF) | 0.782 ± 0.022 | 0.637 ± 0.045 |
| Random Forest | 0.777 ± 0.019 | 0.659 ± 0.031 |
| Neural Network | 0.763 ± 0.005 | 0.640 ± 0.020 |
| QK-SVM (Angle) | 0.769 ± 0.019 | 0.614 ± 0.035 |
| **Angle + CustomAnsatz (VQC)** | **0.758 ± 0.017** | **0.587 ± 0.039** |
| Angle + StronglyEnt (VQC) | 0.717 ± 0.006 | 0.531 ± 0.018 |
| QK-SVM (ZZ) | 0.645 ± 0.007 | 0.246 ± 0.037 |
| QK-SVM (Amplitude) | 0.645 ± 0.000 | 0.000 ± 0.000 |

Full per-run table: `classification/repeated_split_metrics.csv` (165 rows). Aggregates:
`classification/repeated_split_summary.csv`. Paired split-level comparisons:
`classification/paired_comparisons.csv`.

**Do the earlier classification conclusions remain supported?** Yes. Angle+CustomAnsatz
remains the best VQC configuration (0.758 here vs. 0.767 on the original single
partition), and the ordering of model families (classical ≳ QK-SVM(Angle) ≳ best VQC ≫
QK-SVM(ZZ/Amplitude)) is unchanged. With only 5 partitions, paired comparisons are
reported descriptively (mean difference + bootstrap 95% CI), not as significance claims —
see the `caveat` column in `paired_comparisons.csv`.

## Reviewer concern C — Gradient scaling

**What changed:** `barren_plateau.py` was rewritten around a per-parameter variance
statistic (`V_p = Var_i(g[i,p])` for every trainable parameter `p`, not a single number
pooling every initialization and every parameter together), deterministic seeding via
`hashlib.sha256` (the prior version used Python's built-in `hash()`, which is salted
per-process by default and therefore not reproducible run-to-run), and 2,000-replicate
bootstrap 95% CIs on every scaling-regression slope (resampling complete per-initialization
gradient vectors within each grid cell, never individual gradient entries).

**Headline qubit- and depth-scaling slopes** (`log10(mean per-parameter variance)` vs.
grid axis; 2,000-replicate bootstrap 95% CI):

| Ansatz | vs. qubits (2–8) | vs. depth (1–6) |
|---|---|---|
| StronglyEnt | −0.312 [−0.318, −0.306], R²=0.997 — suppression | +0.019 [+0.013, +0.025], R²=0.183 — no suppression |
| BasicEnt | −0.325 [−0.332, −0.318], R²=0.988 — suppression | −0.035 [−0.043, −0.028], R²=0.669 — suppression |
| CustomAnsatz | −0.293 [−0.298, −0.288], R²=0.999 — suppression | +0.048 [+0.042, +0.055], R²=0.741 — no suppression |

Full fits, per-depth and per-qubit breakdowns, and all sensitivity analyses:
`gradients/gradient_scaling_slopes.csv`, `gradients/slope_confidence_intervals.csv`,
`gradients/bootstrap_results/scaling_fits_full.json`.

**Main sensitivity finding:** for StronglyEnt, the classic single-representative-parameter
diagnostic (McClean et al. 2018's original statistic — one arbitrarily-chosen parameter)
gives slope ≈ −0.043, R² ≈ 0.03 (essentially no detectable trend), while the
per-parameter-averaged statistic this round introduces gives slope ≈ −0.312, R² ≈ 0.997.
A single arbitrarily-chosen parameter is not representative of a structured ansatz like
`StronglyEntanglingLayers` — exactly the failure mode the per-parameter correction exists
to catch. Full comparison: `gradients/sensitivity_analysis.csv`.

**Does the evidence support the original barren-plateau interpretation?** Partially, with
an important correction on depth. All three ansätze show real gradient-variance
suppression with increasing qubit count over the tested range. Only BasicEnt shows
suppression with increasing depth — StronglyEnt and CustomAnsatz show a small *positive*
depth slope instead (i.e., no evidence of depth-driven suppression for those two). These
are small simulated circuits (≤8 qubits) with a local observable: this supports finite-size
gradient suppression over the tested range, not a demonstration of asymptotic
barren-plateau scaling, which would require evidence at qubit counts far beyond what
classical simulation can reach. This is a genuine, if partial, weakening of an
unconditional "barren plateau" framing for the depth axis specifically, stated here as
found rather than smoothed over.

## Reviewer concern D — Dataset provenance

**Verified OpenML identity:** `fetch_openml("magic", version=1)` resolves to OpenML
dataset id **40679** (name `"magic"`, version 1) — not 566 (the README's prior claim) and
not 1120 (the reviewer's candidate, `MagicTelescope`). Shape (19,020 × 10), class counts
(12,332 / 6,688), and feature names all match the authoritative UCI MAGIC04 source exactly
— this is a differently-numbered OpenML mirror of the same data, not a different dataset.
Full detail: `dataset/provenance.json`.

**A separate, independently-verified finding, not part of the original question:** using
`FAlpha` (the shower-axis angle to the origin) as a physics-based check — gamma showers
point back at the source (small `FAlpha`), hadron background is isotropic (larger,
~44° mean) — **class 0 is physically gamma and class 1 is physically hadron**, the
opposite of `data_prep.py`'s `"gamma=1, hadron=0"` comment. This is in the **original,
pre-revision** code and therefore affects the original paper's results too, not just this
round. Accuracy, balanced accuracy, and MCC are symmetric and unaffected; precision,
recall, ROC-AUC, and PR-AUC are computed correctly with respect to whichever label is
coded as 1, but any narrative calling those numbers "gamma-detection performance" has
actually been describing hadron-detection performance, and vice versa. **Left
unchanged** — no relabeling, no reruns — pending your decision on the manuscript side;
see `dataset/provenance.json`'s `label_semantics_check` field for the full evidence.

**Were the original results affected?** No — the data loaded was always correct and
unchanged; only its documented identity (OpenML id) and the gamma/hadron naming of the
label need correcting in the manuscript/README, not the underlying numbers.

**Honest disclosure on failures:** `failed_runs.json` contains 331 historical failure
records. All of them occurred during debugging of this round's new parallelization code
(a CUDA/MPS resource-registration issue, a `fork()`-vs-autograd incompatibility, a
`--resume` bug that prevented retrying failed runs, and — the actual root cause of the
most persistent failures — a launcher script missing Python's required
`if __name__ == "__main__":` guard for `multiprocessing`'s `spawn` start method). Each was
diagnosed, fixed in the code committed here, and the affected runs were re-executed
successfully; the grid is currently 100% complete with zero outstanding failures. The
`validate_results.py` suite independently confirms this — see `validation_report.json`.
Kept in `failed_runs.json` per the instruction to preserve logs of failed jobs, not
deleted.

## Limitations

- Gamma/hadron label-semantics inversion (above) — a documentation/narrative issue, not a
  numerical one, left for a manuscript-side decision.
- OpenML flags dataset version 1 as "inactive... issues have been found," with a newer
  version suggested. Data content was independently verified against UCI regardless; the
  specific OpenML-flagged issues were not further investigated.
- Gradient-scaling results are finite-size (≤8 qubits) evidence, not asymptotic
  barren-plateau proof.
- n=5 partitions: paired split-level comparisons are descriptive, not significance tests.
- The optional noise-robustness stage (`noise.py`) was not run this round.
